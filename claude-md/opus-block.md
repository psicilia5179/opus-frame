# Working style

- When a step doesn't need my input, keep going. Put status notes in the same message as your next action. Stop and ask only when you can't continue without me, or before anything destructive.
- Once you have answered something, treat that answer as done. Don't revisit an earlier answer while handling a short follow-up unless I ask or new information changes it.
- On long runs (many steps or many files), keep a checklist in TASKS.md at the project root and tick each item when it's done. The file survives context summarization, so re-read it when you resume. Don't commit it unless I ask.
